# Quiet Cockpit — Essential

Implemented from the exact restored `834227b` tree, through a new branch. No destructive reset and no wholesale restoration of later commits.

## Information architecture

| Area | Contextual views |
| --- | --- |
| Plano / Plan | Unified FL + Score + ETE + Trip Fuel + margin + eligibility; score composition; comparison/analysis; ECON/NORMAL/FAST/MANUAL MAP/RPM; fuel/reserve; W&B; oxygen; cost including alternate; Resilience Lab |
| Rota / Route | Flight Ribbon with physical distance/phase boundaries, TOC/TOD and OFP waypoint selection; METEO/ICE/RIDE/FUEL layers; METEO source state; full ICE and RIDE tools; ETP/PNR; alternate/diversion; GLIDE; Step Climb |
| Em voo / In flight | Virtual Tracker, start/pause/resume/finish, simulation rate and elapsed-time correction; manual NM position; observed fuel; checkpoints; contextual two-field K1/K2 calibration; checkpoint history |

Main navigation has exactly three destinations. Every contextual view has one Back action. Global units, language and text size are under Preferences. Internal views retain mission identity and omit the repeated import form. Technical station tables, the aggregate payload control, fuel breakdown and the previous supplementary KPIs remain available in disclosures.

## Implementation

- `styles.css` is still the only stylesheet: central tokens, base/controls, layout, specialized aviation presentation, grouped responsive sections. No competing stylesheet or framework.
- `layout.js` moves existing DOM controls and result nodes instead of cloning their state. The old four-area navigation is replaced.
- `app.js` retains state, persistence, import, optimization, eligibility and calibration ownership. Its cached optimization snapshot also supplies the automatic recommendation. Applying a configuration remains explicit; the existing marginal confirmation is retained.
- `quiet-cockpit.js` presents actual results, coordinates contextual navigation, and binds tracker/checkpoint observations to the existing operational update path.
- `quiet-position.js` resolves cumulative OFP NM without integer-percent quantization. Full raw navlog distances are retained by the parser. It rejects missing, reversed or incompatible references. Explicit OFP airport endpoints can be used; it never invents intermediate fixes or equal spacing. Repeated-distance fixes retain their identities. Exact waypoint locations show the actual identifier and allow movement to the adjacent fixes.
- The restored reference did not include Resilience, Tracker or the Ribbon. Their domain components were selectively recovered because the requested architecture explicitly includes them. Help Center and the discarded later layouts were not recovered. Additional phase-section instrumentation and an **optional** scenario-evaluation argument support those isolated analyses. Default production arithmetic remains the reference path.
- All module imports use one release cache version, including worker dependencies.

## Operational behavior

The Mission Score is a plain interactive reading adjacent to FL. Partial/unknown evaluations show **NÃO AVALIADO / UNASSESSED**. Restrictive eligibility is evaluated before ranking; it is never inferred from a large Score. The original planned-score snapshot is preserved during manual in-flight updates.

Checkpoint position is stored in fractional NM. The percentage is display only. The same distance drives the Route marker and In flight position. The action is fixed immediately above the mobile navigation, with safe-area/visual-viewport accommodations. Missing position/model/profile/fuel blocks recording. Checkpoints and tracker state use the existing local storage key and validation. Recovered running sessions pause for confirmation. Calibration uses only a recorded cruise context and the original TAS/FF validation, bounds and storage key; it does not change MAP/RPM.

CG Corridors query the engine envelope independently at takeoff and landing weights. **The reference model's envelope is rectangular (127–134 in, maximum 3,000 lb), not a sloping, weight-dependent certified polygon.** Those are the existing estimated coefficients. The visual does not invent varying limits. Overweight phases have no allowed band even when their longitudinal CG is within range. Five occupants, baggage and fuel remain individual inputs. Future envelope calibration belongs in the shared domain model.

The 4D plot uses a responsive `700 × 220` viewBox, 40 px horizontal margins, bounded curves and inset markers. It plots actual fuel-sufficient option counts; it does not imply runway/terrain clearance or operational approval.

## Limits

No physical iPhone/iPad/Android installation or real virtual keyboard was available. Browser layout, font scaling and visual-viewport accommodations are verified; device-level PWA behavior needs physical-device verification. The original viewport preserves pinch zoom and accessibility.

Persistence remains local to this browser/origin, with no new database or cloud synchronization. Weather availability and usable coverage remain independent; external API outages and forecast horizons can legitimately produce UNKNOWN. This redesign is not a fresh validation of a real SimBrief flight, nor a certification/calibration of the estimated aircraft coefficients.

Official source contracts reviewed during implementation: [SimBrief OFP retrieval](https://developers.navigraph.com/docs/simbrief/fetching-ofp-data), [Open-Meteo Ensemble](https://open-meteo.com/en/docs/ensemble-api).
